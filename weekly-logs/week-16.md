Correction from result:
Adaptive identity vs Threat scope reduction; adaptive identity is the principle that trust is never persistent - every request gets re-evaluated based on current context (location, device, behavior). Threat scope reduction is a different principle entirely - it’s about minimizing blast radius if a breach happens (segmentation, limiting what a compromised account can reach), operating on the assumption breach is inevitable. It’s not about re-verifying trust per request; it’s about damage containment after the fact.

Honeytoken vs honeyfile; A honeyfile is typically a decoy file (a fake document like “passwords.xlsx”) planted to detect unauthorized file access. A honeytoken is decoy data embedded within a system - a fake credential, fake API key, or, as in this question, a fake database record - designed to trigger an alert when that specific piece of data gets touched or used elsewhere.
